## 三、阶段 B：多格式输入（Gap 1）

- 数据集 schema 配置注册：`nslkdd`（41 列，现 features.json）、`cicids2017`（78 列，含 Source IP/Destination IP）、`flow`（pcap 提取的流特征子集）

- 诚实声明：无法复刻 CICFlowMeter 全部 78 特征，缺失列按 schema 默认值填充（训练/推理同 schema 对齐即可用）

## 五、阶段 D：告警与处置建议（Gap 4）

**表结构变更先出 SQL（宪法规则；用户本次指令已授权直接开工）：**

```sql
CREATE TABLE t_alert (
  id          BIGINT PRIMARY KEY AUTO_INCREMENT,
  task_id     BIGINT NOT NULL,
  user_id     BIGINT NOT NULL,
  src_key     VARCHAR(64) NOT NULL COMMENT '攻击源(src ip，无 ip schema 用 row 引用)',
  confidence  FLOAT NOT NULL,
  prediction  VARCHAR(20) NOT NULL DEFAULT 'Attack',
  rule_cmd    VARCHAR(512) DEFAULT NULL COMMENT '处置建议命令，绝不自动执行',
  status      VARCHAR(20) NOT NULL DEFAULT 'open' COMMENT 'open|acked|dismissed',
  acked_by    BIGINT DEFAULT NULL,
  created_at  DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at  DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  INDEX idx_user_status (user_id, status),
  INDEX idx_task (task_id),
  INDEX idx_src_time (src_key, created_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

实现：
1. `models.py` 加 Alert ORM + alembic 迁移 `add t_alert`（不碰三张项目表）
2. 新文件 `backend/app/services/alert_service.py`：
   - 检测链路埋点：confidence ≥ `ALERT_CONFIDENCE_THRESHOLD`（config，默认 0.90）且判定 Attack → 生成告警（同 task 同 src_key 去重）
   - 处置建议生成：src_key 是 IP → Windows `New-NetFirewallRule -DisplayName "NADS block <ip>" -Direction Inbound -RemoteAddress <ip> -Action Block`；非 IP → 给"人工复核该记录"建议文案
   - webhook 通知：stdlib urllib POST（不新增依赖），`ALERT_WEBHOOK_URL` 可配，支持 generic 与 feishu 群机器人两种格式，发不出去只记日志不阻断检测
3. 新文件 `backend/app/routers/alerts.py`：GET /alerts（分页，open 优先）、PUT /alerts/{id}/ack、PUT /alerts/{id}/dismiss，归属校验同 tasks 风格；`schemas.py` 加对应模型；`main.py` 注册路由
